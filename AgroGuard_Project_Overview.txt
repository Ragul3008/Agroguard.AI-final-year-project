================================================================
AGROGUARD AI - PROJECT OVERVIEW & ANTIGRAVITY CHANGES
================================================================

1. PROJECT OVERVIEW
---------------------
AgroGuard-AI is a scalable Final Year Project (B.E CSE AI & ML) dedicated to assisting banana farmers identify and treat crop diseases (Panama Wilt, Black/Yellow Sigatoka, Pseudostem Weevil, BBTV, Anthracnose). It combines a modern React frontend with a high-performance Python FastAPI backend, augmented by Deep Learning models and generative AI for agricultural advisories based on ICAR guidelines.

[A] FRONTEND ARCHITECTURE
---------------------
The frontend is built using React (TypeScript) and Vite.
- Technologies: TailwindCSS, Radix UI primitives, Lucide React (icons), React Router, Recharts, and Framer Motion.
- Key Features:
  1. Multilingual Chat & Image Analysis: Farmers upload plant images or ask questions (`Chat.tsx`). The UI supports Indian languages (Tamil, Hindi, Malayalam, Telugu, Kannada, English) and utilizes real-time speech-to-text functionality.
  2. History: Allows revisiting past scans and advisories (`History.tsx`), pulling data directly from local device storage (`localStorage`).
  3. Interactive Horticulture Map: Displays nearby centers for farmers seeking in-person ICAR treatment or validation (`HorticultureMap.tsx`).
  4. Authentication: Secure account creation and login operations via `Login.tsx`.
- Communication: Standard REST API calls using native `fetch()` functions within `src/api.ts`.
- Routing: SPA routing is handled by `React Router DOM` inside `routes.tsx`.

[B] BACKEND API ARCHITECTURE
---------------------
The backend is a robust Python 3.12 application using FastAPI, running asynchronously via Uvicorn.
- Technologies: FastAPI, SQLAlchemy (Async), Google GenAI SDK (Gemini 2.5 Flash), SlowAPI (Rate Limiting), JWT Authentication.
- Core Endpoints (`/api/v1`):
  1. `POST /predict`: The flagship endpoint. It receives an uploaded image (JPEG/PNG), location, and language code. It:
     - Preprocesses the image into a tensor (`image_preprocessing.py`).
     - Feeds it to a custom Deep Learning model (`disease_classifier.py`) to detect banana diseases or Healthy status.
     - Passes findings to `AdvisoryService` to generate a dynamic, native-language treatment plan via Google Gemini based strictly on ICAR-NRCB Trichy guidelines.
     - Finds the nearest horticulture center using `LocationService`.
     - Logs the prediction in the database against the authenticated Farmer.
  2. `POST /speech/transcribe` & `/synthesize`: Handles multilingual voice inputs via OpenAI Whisper model.
  3. `POST /chat` & `/translate`: Facilitates dynamic text-based chat responses acting as an agricultural advisor.
  4. `POST /auth/login` & `/auth/register`: Manages user credentials with JSON Web Tokens.
- Key Mechanics: Database migrations via SQLAlchemy; Strict rate-limiting per IP (e.g., 10 reqs/min for predictions); structured application logging.


================================================================
2. CHANGES MADE BY ANTIGRAVITY (THIS SESSION)
================================================================
The primary objective of this session was resolving severe UI performance bottlenecks (freezing, lagging) and fixing broken regional language translations throughout the stack.

[A] FRONTEND PERFORMANCE OPTIMIZATIONS
---------------------
1. Fixed LocalStorage Freezing (History Tab)
   - Problem: Giant Base64 image strings (up to 5MB each) were being dumped into `localStorage`. `JSON.parse` was hanging the browser when attempting to render the History tab.
   - Fix: Created a strict `compressToThumbnail` canvas utility within `Chat.tsx` that rapidly downscales the heavy uploaded image into a tiny HTML5 Canvas 200px thumbnail (~10KB) *before* saving. Load times are near instant now.

2. Eliminated Typing Lag in the Chat Box
   - Problem: Typing keystrokes felt slow because each letter forced massive SVGs, Maps, and Language dropdowns to re-render continuously.
   - Fix: Locked down rerenders by wrapping complex child components (`AudioButton`, `AnalysisCard`, `HorticultureMap`, `LanguageSelector`) with `React.memo()`, and wrapped main interactive functions (`handleLanguageChange`, `handleSendMessage`) inside `useCallback()`.

3. Implemented Lazy Loading & Code Splitting
   - Problem: An extreme upfront download penalty forced users to get massive graphing features (Recharts, Maps) just to load the Login screen.
   - Fix: Altered `src/app/routes.tsx` to utilize `React.lazy()` and `<Suspense>`.
   - Fix: Modified `vite.config.ts` Rollup `manualChunks` to intelligently bundle heavy libraries (MUI, Radix, Recharts, React) separately on build, drastically cutting initial load times.

4. Prevented "Infinite Hangs" via Timeouts
   - Problem: If the backend LLM stalled from Gemini token rate limits, the UI would freeze on "Analyzing..." for up to 5 minutes waiting unproductively.
   - Fix: Integrated secure `AbortController` timeouts aggressively into `src/api.ts`. Image scans now time out at 25 seconds globally, and Text Chats expire gracefully after 15 seconds.

[B] BACKEND TRANSLATION & LOGIC FIXES
---------------------
1. Restored Full Multilingual Advisory Generation
   - Problem: Even when selecting Tamil/Hindi, the Google Gemini generated English replies. Investigation revealed the `_SYSTEM_PROMPT` in `advisory_service.py` literally contained a hardcoded rule: "10. Response must be in English only". Secondly, the backend `predict_banana_disease` endpoint ignored the `language` dependency.
   - Fix: Erased the English-only rule. Re-wrote the Gemini Prompt instructions dynamically to enforce: "IMPORTANT: You MUST respond in {language}". 
   - Fix: Plumbed the exact `language: str = Form("en")` dependency securely through the FastAPI POST layers to guarantee native translation.

2. Solved Missing Architecture `/chat` Endpoints 
   - Problem: If farmers sent casual questions like "hii", the frontend routed it to `/chat`, which was returning HTTP 404 Not Found since it was entirely unwritten on the backend!
   - Fix: Built entirely new `POST /chat` and `POST /translate` architecture endpoints into `routes.py`.
   - Fix: Bound these logic handlers into `advisory_service.py`, directly hooking them back up to the Gemini Flash Client.

3. Restored Rapid Speed
   - Problem: In a mid-session translation fix step, the system was configured to launch two sequential blocking calls to Gemini specifically to translate the "Disease Name" and "Severity" labels. This chained up to ~12 seconds of wait time per scan.
   - Fix: Removed the two sequential calls. The main Advisory paragraph handles translation entirely now, returning predictions back to a standard blazing fast ~3 seconds. 
   - Fix: Dynamically updated the frontend `Chat.tsx` loader to read "Thinking..." accurately during chat events, rather than statically assuming an image upload.
